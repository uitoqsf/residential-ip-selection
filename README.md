## 三类 IP 的差别在 ASN 和信誉库，不在“干净程度”

目标站点收到请求后，第一件事是拿来源 IP 去查 ASN 数据库，看这个地址块注册在谁名下。Comcast 是 AS7922，Verizon 是 AS701，Cloudflare 是 AS13335，Amazon AWS 是 AS16509。归属托管商的地址块，在主流信誉库里被标记为“托管”，归属消费者运营商的被标记为“住宅”或“消费者”。这个分类由外部数据库决定，IP 地址本身不携带任何这类信息，它只是一个路由编号。

三类 IP 的分野就落在这里。

机房 IP 的 ASN 归 AWS、GCP、OVH、Hetzner 这类托管商，反爬系统在读取请求体之前就已经拿到足够理由降级返回、拦截或弹验证码。它的优势是快、稳、便宜、池子大，适合没有风控的公开站点。

住宅 IP 的 ASN 归消费者运营商，信誉库对它有多年“真实消费者行为”的正向先验，第一步查询轻松通过。指纹检测和行为检测照旧执行，只是容错空间比机房地址宽松。

ISP IP 的 ASN 也归消费者运营商，但流量实际出口的机器在机房。运营商把一段地址分配给了托管客户。ASN 查询显示住宅，信誉库也显示住宅，速度却是数据中心级别。这个品类存在的原因，正是反爬决策基于 ASN 查询结果，而不是机器实际放在哪。

国内行业文章里常说的“运营商 IP”是另一回事，指运营商民用网络里可秒拨、可动态切换的地址，被当作介于机房和住宅之间的中间档。它和上面说的 ISP IP 不是同一个东西，别混着理解。

## 换了住宅 IP 还是 403，网站到底在看什么

住宅 IP 让你过了第一道门，门后面还有四道检查。

**单 IP 请求量。** 一个住宅 IP 每分钟向商品页发出 500 个请求，跟“家庭访客”的行为模式完全对不上。ASN 再干净，请求速率本身就是信号。

**TLS 指纹。** 真实浏览器有特定的加密套件排列、扩展列表和 ALPN 值。Python `requests` 库产生的握手特征跟 Chrome 不一样，这类指纹多年前就进了识别库。住宅 ASN 配上 Python 的 TLS 指纹，等于自己举了牌子。

**请求头异常。** 真实浏览器按固定顺序发送几十个请求头，每个都有具体值。缺 Accept-Language、Sec-Ch-Ua 对不上、顺序跟 Chrome 实际发出的不一致，都会被记为异常。

**行为轨迹。** 真实访客会悬停、滚动、中途离开再回来，爬虫沿着链接直线扫遍所有页面。每次会话的页面数、停留时长、有没有鼠标事件，都在监测范围内。

对使用 SixtyNet 这类固定出口的用户来说，上面四条比“换不换 IP”更关键，因为你根本没有轮换的余地。能做的只有三件事：把速率压到目标站点能接受的水平，把 TLS 指纹换成真实浏览器，把请求头和会话形态做对。

下面这组参数是通用经验值，不是任何平台的官方阈值，可以作为起点再按实际响应调整：普通低风控平台，单个 IP 在一个生命周期内的请求数控制在 20 次以内；电商、资讯这类敏感平台，2 到 3 次请求就该换地址（固定 IP 场景下改成拉开时间间隔）；请求之间随机休眠 2 到 8 秒；超时时间设 10 到 15 秒，设太短会把代理的正常网络抖动误判成失败。另外别在短时间内跨城市、跨地区切换出口，地域突变本身会触发风控。

有 JS 加密和设备指纹校验的站点，光靠 `requests` 过不去，需要 Playwright 或 Selenium 配合无痕模式，再叠加住宅出口。

判断规则很简单：短周期、大批量、可以随时中断重来的采集任务，用动态池；需要保持登录态、维持会话连续性、或者平台把“同一账号换 IP 登录”本身当成风险信号的任务，用静态。SixtyNet 的住宅 IP 属于后者，一台机器一个固定地址，不轮换。

跨境电商多店铺、海外社媒账号这类场景，通常的做法是给每个账号绑一个独立静态 IP，再配防指纹浏览器把设备参数也区分开。这种用法对 IP 的“数量”要求不高，对“稳定”和“归属地正确”要求高，正好是固定住宅 IP VPS 的强项。反过来，一天要抓几百万页面的一次性采集，固定 IP 会被速率限制卡死，租多少台都不划算。

## 常见问题

**住宅 IP 为什么比机房 IP 贵？**

供给结构决定的。机房 IP 可以批量开，住宅 IP 依附在真实家庭宽带线路上，获取和维护成本高一个量级。加上它在 ASN 和信誉库这两层能通过检查，需求端愿意付溢价。

**用了住宅 IP 还是被封怎么办？**

先查三处：单 IP 请求速率是不是明显超出人类范围，TLS 指纹是不是暴露了 Python 或 curl，请求头顺序和字段是否完整。这三项里任何一项出问题，换多少住宅 IP 都没用。

**动态和静态能混用吗？**

能，而且是常见做法。核心账号、需要保持登录态的操作走静态 IP，非核心的、可丢弃的请求走动态池。两套资源分开计费，成本按任务重要性分配。

**按流量买还是按月买机器划算？**

看你需要的是“流量”还是“身份”。请求量大且要分散到多个 IP 的，按流量；需要固定出口、长期在线、身份不能变的，按月。算单位成本之前先确认你的瓶颈是带宽还是 IP 数量。

**采国内站点要不要用美国住宅 IP？**

不要。地理位置和时区对不上，会直接触发地域风控，延迟也高。采国内站点用国内运营商地址，归属地和访问时间才自然。
